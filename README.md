# Coach App

اپلیکیشن فارسی و آفلاین مدیریت مربیگری ورزشی، ساخته‌شده با Flutter.

## وضعیت فعلی

پایه محصول و فاز تکمیل پرونده شاگرد شامل این موارد است:

- معماری Feature-first با جداسازی Domain، Data و Presentation
- رابط فارسی و راست‌به‌چپ
- Flutter ثابت `3.32.6`
- دیتابیس SQLite با Schema و Migration نسخه‌دار
- پرونده ساختاریافته شاگرد
- ثبت، ویرایش، جست‌وجو، بایگانی و بازیابی
- انتخاب‌گرهای حرفه‌ای Bottom Sheet به‌جای Dropdown ساده
- حفظ اطلاعات نسخه قبلی در Migration
- تست‌های مدل، Controller، Widget و Migration
- CI برای Format، Analyze، Test و Build واقعی Android/iOS

## اجرای پروژه

```bash
flutter pub get
flutter run
```

پوشه‌های `android/` و `ios/` بخشی از مخزن هستند. دستور `flutter create .` را روی پروژه اجرا نکنید؛ این کار می‌تواند شناسه برنامه، تنظیمات پلتفرم و پیکربندی امضا را بازنویسی کند.

## FlutLab

Workspace توسعه به شاخه ثابت زیر متصل است:

```text
coach-flutlab-v4-0727
```

توسعه روزمره روی همین شاخه انجام می‌شود. شماره نسخه فقط هنگام Release واقعی تغییر می‌کند و `main` در پایان Milestone پایدار به‌روزرسانی می‌شود.

## شناسه برنامه

```text
com.kingiust.coach
```

این شناسه در Android و iOS ثابت است و بدون برنامه مهاجرت رسمی نباید تغییر کند.

## امضای Android

فایل keystore و `key.properties` خصوصی هستند و نباید وارد GitHub شوند. Release نهایی فقط با کلید ثابت مالک برنامه امضا می‌شود. Buildهای توسعه در نبود keystore از Debug Signing استفاده می‌کنند.

## اصول غیرقابل مذاکره

1. داده محلی منبع اصلی نمایش است.
2. UI به SQLite و Query خام وابستگی مستقیم ندارد.
3. شناسه‌های دامنه پایدار و مستقل از شناسه عددی دیتابیس هستند.
4. حذف عملیاتی به‌صورت Soft Delete انجام می‌شود.
5. هر تغییر Schema دارای Migration و تست حفظ داده است.
6. `INSERT OR REPLACE` برای Entityهای دارای ارتباط ممنوع است.
7. برنامه منتشرشده در آینده Immutable و Revisionدار خواهد بود.
8. Import باید Transactional، Idempotent و قابل تکرار باشد.
9. نسخه قرارداد تبادل داده مستقل از نسخه اپ است.
10. اطلاعات حساس، توکن، رمز و کلید امضا وارد کد یا Log نمی‌شوند.
